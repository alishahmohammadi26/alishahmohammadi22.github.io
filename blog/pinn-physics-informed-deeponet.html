Physics-Informed DeepONet: Operator Learning Without Solution Data, and Parameter Estimation at Scale

Combining the universal approximation theorem for operators with physics-informed training, and using DeepONet to solve inverse problems across entire parameter families simultaneously.

Apr 2026 30 min read Advanced Scientific ML Physics-Informed Operator Learning Parameter Estimation notebooks: 04_Research_Papers/11 & 12
Section 01

The Data Bottleneck in Standard DeepONet

The previous article established DeepONet's central capability: by learning the solution operator of a PDE, a single trained network can evaluate any input function-to-solution mapping in a millisecond forward pass. The economics are compelling, train once, deploy everywhere. But there is a hidden cost buried in the training phase that deserves scrutiny.

Training a standard DeepONet requires a dataset of $(u_i, s_i)$ pairs: input functions and their corresponding output functions. For the antiderivative example, generating 1,000 pairs took negligible time because the antiderivative can be computed analytically. But for realistic PDE operators, the heat equation, reaction-diffusion, Navier-Stokes, each pair requires running a classical solver (FEM, FD, spectral method) to convergence. For a 3D CFD simulation, a single solve can take hours. Generating 1,000 training pairs means 1,000 solver runs, which can dwarf the DeepONet training time itself.

The labeled data bottleneck For standard DeepONet, generating N training pairs requires N full PDE solves. For expensive simulations (3D CFD, nonlinear FEM, multiphysics reactors), this upstream cost can be prohibitive, the same cost that operator learning was supposed to eliminate.

This is not a theoretical concern. In pharmaceutical process modeling, a single coupled reaction-transport simulation of a continuous manufacturing reactor with realistic kinetics and heat effects can take 30–90 minutes on a CPU cluster. Building a training dataset of 1,000 such simulations is a 30,000–90,000 CPU-hour project. The question is: can we train a DeepONet with little or no labeled solution data?

The answer, developed by Wang, Wang & Perdikaris in 2021 (Science Advances), is yes, by applying the governing physics directly as the training signal for the operator. This is the core idea of Physics-Informed DeepONet (PI-DeepONet).

Section 02

Physics-Informed DeepONet

The key insight is exactly analogous to how PINNs eliminate the need for labeled solution data when training a function approximator: substitute the PDE residual for the data loss (or add it as a regulariser). Applied to an operator, the physics loss requires that the output of the DeepONet, which is a function of both the input function $u$ and the query location $y$, satisfies the governing PDE at every collocation point, for every input function in the training distribution.

For a general PDE $\mathcal{R}[s] = 0$ with solution operator $\mathcal{G}: u \mapsto s$, the total loss is:

$$\mathcal{L} = \underbrace{\mathcal{L}_{\text{data}}}_{\text{labeled pairs}} + \lambda \underbrace{\mathcal{L}_{\text{physics}}}_{\text{PDE residual on operator output}}$$

where the physics component evaluates the PDE residual applied to the operator's output:

$$\mathcal{L}_{\text{physics}} = \frac{1}{N_f \cdot N_y} \sum_{k=1}^{N_f} \sum_{j=1}^{N_y} \left|\mathcal{R}\bigl[\mathcal{G}(u_k)\bigr](y_j)\right|^2$$

Here $\{u_k\}_{k=1}^{N_f}$ is a set of input functions sampled from the training distribution, and $\{y_j\}_{j=1}^{N_y}$ are collocation points in the output domain. The operator output $\mathcal{G}(u_k)(y_j) = \sum_{p} b_p(u_k) \cdot t_p(y_j) + b_0$ must satisfy the PDE at each $(u_k, y_j)$ pair.

In the pure physics-informed limit ($\mathcal{L}_{\text{data}} = 0$), no labeled pairs $(u_i, s_i)$ are required at all. The network is supervised entirely by the governing equation and boundary/initial conditions. This is the setting demonstrated in the notebook for this article.

Figure 1. PI-DeepONet training architecture. The operator output $\mathcal{G}(u_k)(x,t)$ is supervised by two loss terms: an optional data loss comparing against labeled solutions, and a mandatory physics loss enforcing the PDE residual via automatic differentiation through the trunk network.

Section 03

Why This Is Harder Than a Standard PINN

At first glance, PI-DeepONet looks like a straightforward extension of the PINN idea to the operator setting. But several structural differences make it substantially more challenging to train.

1. The input is a function, not coordinates

In a standard PINN, the only input to the network is a coordinate vector $(x, t) \in \mathbb{R}^d$. The physics loss at a collocation point is simply evaluated by passing $(x_j, t_j)$ forward and computing gradients. In PI-DeepONet, the input is a pair $(u_k, y_j)$ where $u_k$ is an entire function (encoded as $m$ sensor values). The physics loss must hold simultaneously for many different input functions, not just at many spatial locations. The effective "space" over which the physics must hold is infinite-dimensional.

2. Gradients flow through the trunk only

Computing the PDE residual requires differentiating the operator output with respect to the query location $y$. In the DeepONet output $\mathcal{G}(u)(y) = \mathbf{b}(u) \cdot \mathbf{t}(y) + b_0$, only the trunk depends on $y$. The gradient is:

$$\frac{\partial}{\partial y}\mathcal{G}(u)(y) = \mathbf{b}(u) \cdot \frac{\partial \mathbf{t}(y)}{\partial y}$$

This means the physics loss backpropagates through the trunk network but does not directly update the branch, the branch is only updated via the physics loss through the product $\mathbf{b}(u) \cdot \partial_y \mathbf{t}(y)$. This asymmetry in gradient flow can create training imbalances: the trunk may learn quickly (it is directly constrained by the PDE) while the branch updates slowly. Careful learning rate tuning and periodic activation functions in the trunk (which have better-behaved higher derivatives) help.

3. The loss landscape is nested

The outer loop is over input functions $\{u_k\}$; the inner loop is over collocation points $\{y_j\}$ for each function. In practice this means the physics loss is a double sum, a mini-batch must cover both function diversity and spatial diversity to avoid gradient bias. A batch that samples only a single input function is equivalent to a PINN for that one instance; the operator generalisation requires that many diverse input functions appear in each gradient step.

Section 04

The Reaction-Diffusion Operator Benchmark

The canonical benchmark from Wang, Wang & Perdikaris (2021) is the nonlinear reaction-diffusion equation:

$$\frac{\partial s}{\partial t} = D\frac{\partial^2 s}{\partial x^2} + k\,s(1-s), \quad x \in [0,1],\; t \in [0,T]$$

with homogeneous Neumann boundary conditions $\partial_x s(0,t) = \partial_x s(1,t) = 0$ and initial condition $s(x,0) = u(x)$. With $D = 0.01$ and $k = 1$, this equation describes Fisher's reaction-diffusion: a species that both diffuses spatially and grows logistically toward carrying capacity. The solution can exhibit complex transient profiles before settling to $s \equiv 1$.

The operator to learn is $\mathcal{G}: u(x) \mapsto s(x,t)$, the map from any initial condition to the full space-time solution field. The trunk takes $(x,t) \in \mathbb{R}^2$ as input, producing basis functions over the 2D output domain. The branch takes $u$ evaluated at $m$ spatial sensors.

The antiderivative example from the notebook (notebook 11) uses this same architecture but with the simpler first-order ODE $ds/dy = u(y)$ as the PDE constraint, demonstrating the method with zero labeled solution data:

Python · physics-informed training (zero labeled data) 
# The problem: learn G: u → s  where  ds/dy = u(y),  s(0) = 0
# No ground-truth s anywhere — only the ODE and BC.

def sample_batch(bs):
    idx = np.random.randint(0, N_fun, bs)
    u_b = U_t[idx]                       # (bs, m) branch input
    y = torch.rand(bs, 1, device=device,
                   requires_grad=True)   # query points (need grad for PDE)
    # Interpolate u(y) for the RHS of the ODE
    yi = (y.detach().cpu().numpy().ravel() * (m-1))
    lo = np.floor(yi).astype(int); lo = np.clip(lo, 0, m-2)
    fr = yi - lo
    u_at_y = U[idx, lo]*(1-fr) + U[idx, lo+1]*fr
    u_at_y = torch.tensor(u_at_y, dtype=torch.float32,
                          device=device).view(-1, 1)
    return u_b, y, u_at_y

def boundary_batch(bs):
    idx = np.random.randint(0, N_fun, bs)
    return U_t[idx], torch.zeros(bs, 1, device=device)

opt = torch.optim.Adam(model.parameters(), lr=1e-3)

for ep in range(10000):
    opt.zero_grad()

    # Physics loss: ds/dy = u(y) at random query points
    u_b, y, u_at_y = sample_batch(2000)
    s = model(u_b, y)
    s_y = torch.autograd.grad(s, y, torch.ones_like(s),
                               create_graph=True)[0]
    L_phys = torch.mean((s_y - u_at_y)**2)

    # Boundary condition: s(0) = 0
    ub, y0 = boundary_batch(500)
    L_bc = torch.mean(model(ub, y0)**2)

    loss = L_phys + L_bc
    loss.backward(); opt.step()

    if ep % 2000 == 0:
        print(f"epoch {ep:5d} | L_phys {L_phys.item():.2e} | L_bc {L_bc.item():.2e}")

# Trained with ZERO solution labels — only the ODE and BC

The crucial line is s_y = torch.autograd.grad(s, y, ...). This differentiates the operator output with respect to the trunk query $y$ using PyTorch autograd, the gradient flows through the trunk network, computing $\partial_y \mathcal{G}(u)(y) = \mathbf{b}(u) \cdot \partial_y \mathbf{t}(y)$. The physics residual $\partial_y s, u(y) = 0$ then provides the training signal without requiring any labeled $(u_k, s_k)$ pairs.

Section 05

Parameter Estimation with Operator Learning

The most consequential application of PI-DeepONet is not forward prediction, it is inverse parameter estimation. Inverse Problems in this series demonstrated how a PINN can recover unknown PDE parameters by including them as learnable variables in the physics loss. The cost: a separate PINN must be trained for each new measurement dataset, each requiring 30–120 seconds of gradient descent.

Operator learning offers a fundamentally different paradigm. Instead of treating $D$ and $k$ as fixed physical constants, make them part of the branch input. The augmented branch encodes:

$$\text{branch input} = [u(x_1),\, \ldots,\, u(x_m),\, D,\, k]$$

Now the operator maps $(u, D, k, x, t) \to s(x,t)$: it is the solution operator over the entire parameter space simultaneously. Training this operator requires collocation tuples $(u_k, D_k, k_k, x_j, t_j)$ with the physics loss evaluated at each combination, but crucially, the same training run learns the operator for all $(D, k)$ in the training distribution.

Once the operator is trained and its weights frozen, given new sensor measurements $\{s_{\text{obs}}(x_i, t_i)\}$, the inverse problem reduces to a small optimisation over the branch input alone:

$$\min_{D, k} \sum_i \left|\mathcal{G}(u_0, D, k)(x_i, t_i), s_{\text{obs}}(x_i, t_i)\right|^2$$

The operator weights are frozen, only $D$ and $k$ (two scalars) are optimised. This turns a nonlinear PDE inverse problem into a 2-parameter regression with a cheap-to-evaluate surrogate. Gradient descent on this 2D problem converges in seconds, compared to the 30–120 second full PINN inverse solve. More importantly, the same frozen operator can be used for unlimited new measurements without any retraining, it is a reusable inference engine for the entire parameter space.

PHASE 01
Train Operator Offline
Sample $(u_k, D_k, k_k)$ from prior. Run PI-DeepONet training with physics loss over entire parameter family. Cost: paid once.
PHASE 02
Deploy: Weights Frozen
Operator deployed. All weights fixed. Forward inference: single pass (<1 ms). Operator can answer any $(u, D, k) \to s$ query instantly.
PHASE 03
Inverse Problem
New measurements arrive. Optimise only $(D, k)$, 2 scalars, against frozen operator. Converges in seconds. Operator reused for any future dataset.

Figure 2. The three-phase deployment cycle for PI-DeepONet-based parameter estimation. The upstream training cost is paid once; all subsequent inverse queries use the frozen operator with only a 2-parameter optimisation.

The key mechanism that makes this possible is that the learned operator is a smooth, differentiable function of $(D, k)$ through the branch network. Gradients of the data misfit with respect to $(D, k)$ are computed via backpropagation through the frozen operator, the same mechanism used for regular gradient descent, but on a much smaller manifold (2D vs 27,000D for full PINN retraining).

Section 06

Architecture Improvements for PI-DeepONet

Notebook 12 (Architectures and Training) documents the key upgrades that define current best practice for both PINNs and PI-DeepONet. These are not theoretical niceties, they are practical requirements for achieving accurate results on difficult problems.

Modified MLP with Gating

Wang et al. 2022 identified that standard MLP initialization causes gradient pathologies in deep PDE networks. The "Modified MLP" introduces two encoder branches $U = \sigma(W_1 x + b_1)$ and $V = \sigma(W_2 x + b_2)$, then applies a gating transform at each hidden layer:

$$H^{(k+1)} = \sigma\!\left(W^{(k)} H^{(k)} + b^{(k)}\right) \odot U + \left(1 - \sigma\!\left(W^{(k)} H^{(k)} + b^{(k)}\right)\right) \odot V$$

The gate $\sigma(W H + b) \in (0,1)$ interpolates between the two encoder representations at each layer depth. This provides stable gradients throughout training, the encoders prevent signal vanishing, and empirically reduces the number of epochs required by 3–5x for stiff problems.

Fourier Feature Embeddings

Spectral bias, the tendency of plain MLPs to learn low-frequency components first, is particularly damaging for the trunk network in PI-DeepONet, since the trunk must learn basis functions that capture the full frequency content of the PDE solutions. Random Fourier features (Tancik et al. 2020; Wang et al. 2021) map the trunk input through a random frequency embedding before the MLP:

$$\gamma(y) = \left[\cos(2\pi B_1 y),\, \sin(2\pi B_1 y),\, \ldots,\, \cos(2\pi B_n y),\, \sin(2\pi B_n y)\right]$$

where $B_i \sim \mathcal{N}(0, \sigma^2)$ are randomly sampled frequencies with bandwidth $\sigma$ chosen to match the expected frequency content of the target operator. For the high-frequency Poisson benchmark in notebook 12, this single change reduces the relative $L^2$ error from $\sim 0.5$ (plain MLP) to $\sim 10^{-3}$ (Fourier features) after the same number of training epochs.

Python · Fourier feature trunk 
class FourierTrunk(nn.Module):
    """Trunk with random Fourier feature embedding + MLP."""
    def __init__(self, in_dim=2, p=50, width=100,
                 n_feat=64, sigma=4.0):
        super().__init__()
        B = torch.randn(in_dim, n_feat) * sigma
        self.register_buffer("B", B)       # fixed random frequencies
        self.net = nn.Sequential(
            nn.Linear(2*n_feat, width), nn.Tanh(),
            nn.Linear(width, width), nn.Tanh(),
            nn.Linear(width, p), nn.Tanh()
        )

    def forward(self, y):
        # y: (N, in_dim)  e.g. (x, t) pairs
        proj = 2 * np.pi * y @ self.B        # (N, n_feat)
        feat = torch.cat([torch.cos(proj), torch.sin(proj)], dim=1)
        return self.net(feat)                # (N, p)

POD-DeepONet

When a small number of labeled solutions is available (say, 50–200), the POD-DeepONet variant uses them constructively rather than as direct supervision. POD (Proper Orthogonal Decomposition, also known as PCA on the solution snapshots) extracts the empirically optimal basis functions from the available solutions. These POD basis functions are used to initialise or replace the trunk network outputs, the trunk is pre-conditioned to represent the relevant solution space before training begins. The branch network then learns to predict POD coefficients rather than raw function values, which is a substantially easier regression task. Wang et al. 2022 showed this variant achieves accuracy competitive with standard DeepONet trained on 10x more labeled data.

PirateNets and Deep Operator Networks

Wang et al. 2024 introduced PirateNets (Physics-Informed Residual Adaptive Networks), a training protocol that uses physics-informed initialization for each residual block, ensuring that very deep networks (40+ layers) train stably. For PI-DeepONet applied to complex multi-scale PDEs, this enables substantially deeper architectures than the 3-layer MLPs in the baseline, capturing richer operator structure at the cost of more careful initialization.

Section 07

Training Tips for PI-DeepONet

Getting PI-DeepONet to converge reliably on difficult PDEs requires attention to several practical details that are not always discussed in papers focused on theoretical contributions.

Issue Symptom Remedy
Function-level batch bias Physics loss stagnates; model learns the mean of the distribution Sample diverse mini-batches: at least 128 distinct input functions per gradient step
Loss imbalance ($\mathcal{L}_{\text{phys}} \gg \mathcal{L}_{\text{data}}$) Model ignores data loss; may satisfy PDE but miss observations Normalise each loss term separately; use NTK-based dynamic weighting (Wang et al. 2022)
Gradient explosion in physics loss NaN within first 100 epochs Clip gradients: torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
Slow convergence on temporal PDEs Accurate at $t=0$, degraded at large $t$ Causal training: weight collocation points by $e^{-\epsilon \cdot t}$, decrease $\epsilon$ over training
High-frequency trunk features Operator fails on rapidly oscillating inputs Fourier feature embedding in trunk; choose $\sigma$ to match the spectrum of target PDE solutions
Branch-trunk gradient asymmetry Branch weights barely change; operator ignores input function details Add a small direct data loss on the branch output (coefficient-level supervision); or reduce trunk learning rate

The learning rate schedule matters considerably for PI-DeepONet. A warm-up phase (100–500 steps of linear increase from $10^{-5}$ to $10^{-3}$) followed by cosine decay prevents early overfit to the initial function samples. The transition from Adam to L-BFGS in the final training phase (standard practice for PINNs) is also beneficial for PI-DeepONet when a small labeled dataset is available, as L-BFGS can drive the data loss to near machine precision.

Section 09

Industrial Application: Digital Twin for Pharmaceutical Manufacturing

The methods developed in this article series, from basic PINNs to PI-DeepONet, are not academic constructs. They address concrete engineering challenges in pharmaceutical manufacturing. Let me be specific about how this applies to continuous manufacturing reactor modeling.

The Process Problem

A continuous pharmaceutical manufacturing reactor involves coupled transport phenomena: reactant concentration profiles $c(x,t)$ governed by a convection-diffusion-reaction PDE, temperature profiles $T(x,t)$ from the heat equation with reaction-generated source terms, and outlet concentration $c_{\text{out}}(t)$ measured by PAT (Process Analytical Technology) sensors in real time. The governing equations form a coupled system:

$$\frac{\partial c}{\partial t} + v\frac{\partial c}{\partial x} = D_c \frac{\partial^2 c}{\partial x^2} - r(c, T)$$ $$\frac{\partial T}{\partial t} + v\frac{\partial T}{\partial x} = D_T \frac{\partial^2 T}{\partial x^2} + \Delta H_r \cdot r(c, T)$$

where $r(c, T) = k_0 e^{-E_a/RT} c^n$ is an Arrhenius reaction rate. The parameters of interest, $k_0$, $E_a$, the reaction order $n$, heat of reaction $\Delta H_r$, are often imprecisely known and may drift over time as raw material properties change between batches.

The DeepONet Digital Twin

A DeepONet trained on this coupled system maps:

$$\mathcal{G}:\; \bigl(c_{\text{in}}(t),\; F(t),\; k_0,\; E_a,\; n\bigr) \;\longmapsto\; \bigl(c(x,t),\; T(x,t),\; c_{\text{out}}(t)\bigr)$$

The branch encodes the inlet concentration profile $c_{\text{in}}(t)$ (sampled at $m$ time points) plus the scalar process parameters concatenated into the branch input vector. The trunk encodes $(x, t)$. Once trained on a distribution of operating conditions using PI-DeepONet (with physics supervision from the PDE system and a small number of validated simulation pairs), the digital twin:

  • Real-time prediction: given the current inlet profile from flow meters, predict $c_{\text{out}}(t)$ for the next 30 minutes in <1 ms, enabling proactive control.
  • In-loop parameter estimation: when PAT sensor readings arrive, solve the inverse problem (recover $k_0$, $E_a$ from $c_{\text{out}}$ measurements) in seconds, early detection of raw material variability.
  • Design space exploration: sweep 10,000 combinations of flow rate, temperature setpoint, and feed concentration to identify the feasible operating region, completed in under 30 seconds.
  • Uncertainty quantification: sample 50,000 parameter draws from a prior distribution and propagate through the operator to obtain posterior predictive distributions, enabling probabilistic specification testing.

This is precisely the application domain where the operator learning advantage is transformative. Classical mechanistic models take 30–90 minutes per solve; a PINN digital twin requires retraining for each new operating condition. A PI-DeepONet digital twin trained once covers the entire operating envelope at inference speeds compatible with real-time control loops and ICH Q13 continuous manufacturing process monitoring requirements.

ICH Q13 & real-time release relevance Continuous manufacturing under ICH Q13 requires a Process Control Strategy with real-time monitoring and control capability. A PI-DeepONet digital twin provides the millisecond-speed physics-consistent surrogate needed for in-loop model predictive control and real-time release testing, replacing expensive CFD runs with a learned operator that respects the governing physics.
Section 10

State of the Field and Open Problems

As of early 2026, PI-DeepONet and related physics-informed operator learning methods have moved from proof-of-concept to practical applicability for a significant class of problems. Understanding the current capabilities and limitations is essential for choosing when to deploy these methods.

Where PI-DeepONet Works Well

Parabolic PDEs (heat equation, diffusion-reaction, Black-Scholes) and elliptic PDEs (Poisson, Laplace, linear elasticity) are the sweet spot. These problem classes have smooth, bounded solutions with no shocks or discontinuities, making the operator structure compact and the physics loss well-conditioned. Test errors of $10^{-3}$ to $10^{-4}$ in relative $L^2$ norm are routinely achievable with reasonable architectures.

Where It Remains Challenging

Hyperbolic PDEs with shocks (Euler equations, conservation laws) remain difficult. The issue is structural: the solution operator is not continuous in the function topology assumed by the Chen & Chen theorem when shocks form. The output function $s = \mathcal{G}(u)$ can have sharp discontinuities even when the input $u$ is smooth, which requires a very large $p$ to represent accurately. Current approaches use ENO-type numerical dissipation in the training loss or reformulate the problem in weak (integral) form to handle shocks.

Open Problems

Geometry variation: current DeepONet formulations assume a fixed domain $\Omega$. Handling shape optimization (varying $\Omega$ as part of the operator input) is an active research direction, graph neural operators are better positioned for this, but at significant computational cost for complex 3D geometries.

Uncertainty quantification: a point-estimate operator does not quantify its own epistemic uncertainty (uncertainty due to limited training data) or aleatoric uncertainty (uncertainty in the PDE parameters). Bayesian neural operators (using variational inference or Monte Carlo dropout) are under active development, but the computational cost of propagating uncertainty through the operator training is substantial.

3D industrial geometries: the memory and computational requirements of PI-DeepONet scale with the dimension of the query space. For 3D geometries with $10^5$–$10^6$ degrees of freedom, the trunk must evaluate at high-dimensional $(x,y,z,t)$ inputs, which taxes standard MLP architectures. Combination with model-order reduction (POD-DeepONet for 3D) or attention-based architectures is likely needed.

Multi-fidelity training: combining cheap low-fidelity simulations (coarse grid FEM) with expensive high-fidelity data in a unified operator learning framework, analogous to multi-fidelity GPs in the surrogate modeling literature, is an open and practically important problem.

Series conclusion This series has traced the arc from basic PINNs (a network that solves one PDE instance) through inverse problems, adaptive sampling, and finally to operator learning, the framework where a single trained network encodes an entire family of PDE solutions. The common thread is automatic differentiation as a physics-enforcement mechanism. Whether encoding boundary conditions in a single network or enforcing a PDE residual across millions of input functions, the same backpropagation machinery that powers deep learning turns out to be exactly what is needed to incorporate physical law into learned models. The next frontier, 3D multiphysics operators for industrial digital twins, is where this machinery will find its most consequential application.
